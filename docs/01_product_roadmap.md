# 01｜CookingApp 全生命周期产品路线图

更新日期：2026-08-14  
用途：记录所有版本中新增、完成、延期、替代和放弃的功能。当前版本的具体执行只写入 [`02_v2_workboard.md`](./02_v2_workboard.md)。

## 1. 状态定义

| 状态 | 含义 |
|---|---|
| 已完成 | 已进入正式基线，并完成对应验收。 |
| 进行中 | 正在开发、合并、迁移、部署或实机验收。 |
| 已计划 | 已确定版本，但尚未开始。 |
| 候选 | 值得保留，尚未承诺版本。 |
| 已延期 | 明确保留，但因前置条件移到以后。 |
| 已替代 | 目标保留，方案已经换成另一种实现。 |
| 已放弃 | 不再实施，并记录原因。 |

## 2. 版本总览

| 版本 | 定位 | 状态 | 完成边界 |
|---|---|---|---|
| V1 | 基础设施版 | 已完成 | 登录权限、来源导入、菜谱 CRUD、日志、分享边界、备份恢复、域名发布和 10 条真实闭环。 |
| V2 | 初步应用版 | 进行中 | 厨房词典、采购清单、线上冰箱、公开菜谱运营、多来源导入、繁中本地化、成本与可靠性增强。 |
| V3 | 自动化与并行厨房版 | 已计划 | 自动转写/OCR/AI 结构化、保质期提醒、后台批处理、多菜谱滑动、多锅与多厨房调度。 |
| V4+ | 协作与平台化 | 候选 | 多人共同编辑、原生 App/微信端、推荐与更完整生态，视真实使用决定。 |

## 3. V1｜基础设施版

### 已完成

- 邮箱注册、确认、登录、密码找回、密码修改与 Turnstile；
- Supabase migrations、RLS、角色表、私有 Storage 策略和 115/115 越权测试；
- B 站 JSON 导入、BV 去重、来源待办、手工录入、草稿和做菜日志；
- 菜谱 CRUD、厨房模式、标签组合筛选和来源追溯；
- 公开菜谱白名单快照与管理员审核基础；
- DEV / PROD 分离，JSON/CSV 备份与隔离恢复；
- 手机主流程、异常重试、第二账号隔离和 10 条真实内容验收；
- GitHub、Sites、自定义域名和 HTTPS 发布链路。

详细经验与范围调整见 [`00_v1_technical_experience.md`](./00_v1_technical_experience.md)。

## 4. V2｜初步应用版

### 4.1 厨房词典与地区本地化

- 进行中：食材与厨具的简中、英文、德文基础词典；
- 进行中：德国普通超市 / 亚超优先分类和用户购买经验；
- 已计划：繁体中文 `zh-TW` 界面；
- 已计划：台湾地区词汇层，而不是只做字符级简繁转换；
- 已计划：用户在设置中选择 `zh-CN` / `zh-TW`，保存在现有 `profiles.locale`；
- 已计划：地区词条来源、审核状态、别名与版本；
- 已延期：奥地利、瑞士等更细地区词汇，等德国实际使用后扩展。

### 4.2 选菜、采购、库存与成本

- 进行中：菜谱加入采购车、多菜食材聚合、德超/亚超清单和 CSV；
- 已合入 main：采购行可勾选“已购买”，复制与 CSV 自动排除本次已购买食材；
- 已合入 main：账号级“线上冰箱”保存常备食材/调料，采购清单自动排除已有库存；支持“用完了”二次确认后移出库存；
- 已完成数据库结构：`pantry_items` 在 DEV / PROD 均启用 owner-only RLS；业务备份升级并覆盖线上冰箱数据；
- 已计划：份数缩放、同单位合并；
- 已计划：如真实使用需要，再把“本次已购买”从浏览器状态升级为跨设备采购会话；
- 已计划：采购价格、币种、包装净量、商店、每次做菜成本和每人份成本；
- 已计划：调料按次数或固定估价均摊；
- 已延期：实时门店库存和价格抓取，必须保留地区、时间与来源，不能硬编码。

### 4.3 公开菜谱与运营

- 进行中：私人菜谱申请公开、管理员审核、公开快照与只读公开库；
- 已合入 main：成品图片封面与公开点赞；
- 已计划：最新/热门排序、管理员批量审核和运营标签；
- 已计划：公开内容的再次修改必须重新审核。

### 4.4 多来源导入

- 已合入 main：统一 `SourceAdapter` / `SourceDraft` 与通用分享文本入口；
- 进行中：B 站、下厨房、小红书和普通网页真实样本验收；
- 已合入 main：下厨房普通菜谱 URL 自动转换为 MIP 读取，预填标题、作者、用料和步骤；
- 已替代：小红书服务器自动抓取不作为主方案，改为“分享链接识别 + 浏览器人工通过登录/验证 + 页面提取器 + CookingApp JSON”；
- 已合入 main：小红书可弹出独立浏览器小窗口查看原页，并提供 App deeplink；小窗口只负责查看和人工验证，不跨域读取正文；
- 已计划：小红书视频自动转写/OCR/结构化放入 V3；
- 已放弃：通过绕过登录、验证码、浏览器风控或反爬稳定抓取任意受限内容。

### 4.5 可靠性、安全与维护

- 已计划：德国地区验证邮件未达排查；
- 已计划：正式扩大注册前配置或评估自定义 SMTP；
- 已计划：Storage 图片备份恢复演练；
- 已计划：错误监控、访问日志、用量告警和自动化 GUI 回归；
- 已计划：DEV 新菜谱向 PROD 只追加、不覆盖的增量工具；
- 已计划：逐步拆分 `CookingProvider`，把页面直连 Supabase 迁入 service/repository；
- 已计划：统一版本号、CHANGELOG、迁移、GitHub 和 Sites 发布门禁。

## 5. V3｜自动化、库存提醒与并行厨房版

### 5.1 来源自动化

- 自动字幕 / 音频转写；
- 视频关键帧 OCR；
- 小红书等视频来源的受控辅助导入与人工核验；
- AI 菜谱候选结构化；
- 大批量后台队列、断点续传和失败重试；
- 来源证据与个人修改的差异比较和细粒度回滚。

### 5.2 线上冰箱增强

- 为库存项增加购买日期、开封日期和可选保质期；
- 临期提醒与已过期提醒；
- “用完了 / 丢弃 / 补货”状态与采购清单联动；
- 提醒只作为辅助，不自动判断真实食品安全状态；
- 视真实使用再增加数量、包装单位和多存放位置（冰箱 / 冷冻 / 常温）。

### 5.3 多菜谱并行厨房

- 一次选择多道菜进入“本次做菜”；
- 手机左右滑动切换菜谱；
- 平板双栏或多栏同时显示；
- 每道菜独立保存当前步骤、完成状态和计时器；
- 全部菜总览集中提示下一步、翻面、关火和预计完成时间；
- 步骤绑定锅具、灶位、烤箱等资源；
- 单厨房自动调度，再扩展多人 / 多厨房协同与移动交接。

## 6. 候选功能池

- 周菜单与家庭库存闭环；
- Open Food Facts 或其他可追溯商品数据；
- 营养估算与来源标记；
- 基于历史评分、时间、库存和目标的推荐；
- 多人共同编辑与协作任务；
- 微信登录、微信小程序或原生 App；
- 离线优先与更完整的 PWA 能力。

候选功能只有在进入具体版本并写入 `02` 后才算承诺。

## 8. 路线图维护规则

1. 新需求先写入本文件并标记版本与状态；没有版本的进入候选池。
2. 开始实施时同步到 `02`，写负责人、前置条件和完成定义。
3. 用户反馈先进入 `99`，确认处理后再转成 `02` 任务。
4. 发布后更新 CHANGELOG；版本结项后把经验沉淀到对应 `00` 类复盘。
5. 删除、替代和延期不能从历史中抹掉，必须保留原因和日期。
