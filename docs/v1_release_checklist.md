# CookingApp 第一版发布剩余工作

更新时间：2026-08-09。当前目标仍是“仅本人可访问”的第一版；此清单不代表已经发布生产版本。

## 已完成

- Supabase 基础表、RLS、邮箱魔法链接登录和私有 Storage。
- B 站收藏夹 JSON 导入、BV 号查重、导入任务与逐条审计。
- 菜谱 CRUD、厨房模式、做菜日志、中英德食材词典、标签、备份导出和只读分享页面骨架。
- 视频审核页、登录后 B 站 AI 字幕导出工具、翻译采购分区和成本核算代码骨架。
- 手动录入工作台：来源、字幕、食材、步骤、证据和核验状态一次写入 Supabase。
- 两条字幕样本验证：`BV1CQ4y1j7or` 183 段，`BV1JmbVzfEev` 76 段。
- 数据库触发器函数已撤销匿名和普通登录用户的直接 RPC 执行权限。

## 发布前必须完成

| 优先级 | 工作 | 验收条件 |
|---:|---|---|
| P0 | 真实内容闭环 | 至少 10 条视频完成“来源版 → 个人版 → 做菜日志”，其中缺失克数和火候明确标为待核验。 |
| P0 | 手动录入实机验收 | 登录状态下新增、重复保存、同视频多配方、字幕导入均不重复建记录。 |
| P0 | RLS 隐私测试 | 未登录用户不能读取私人菜谱、字幕、导入原始数据和日志；登录用户只能读写自己的数据。 |
| P0 | 登录与回调 | 本地域名和最终域名分别完成魔法链接回调验证，不出现跳回未登录。 |
| P0 | 数据备份与恢复演练 | 能导出完整 JSON；在空测试项目按 migration 重建并恢复一份样例数据。 |
| P0 | 手机端主流程 | 手机可登录、录入、编辑、查看厨房模式、写日志和退出登录。 |
| P0 | 错误处理 | 保存中、保存失败、空数据、重复导入、网络中断均有明确反馈且可重试。 |
| P1 | 分享边界 | 公开页面只返回白名单菜谱字段，不出现字幕原文、私人日志、邮箱或导入元数据。 |
| P1 | 字幕效率 | 正式使用页面内导出 JSON，不再通过云端浏览器边播放边采集；记录 AI 错词和人工核验状态。 |
| P1 | 画面克数流程 | 第一版允许手动录入画面克数；OCR 自动识别留到后续，不阻塞发布。 |
| P1 | 成本数据结构验收 | 用 3 道真实菜验证重量、体积、按次数均摊和每人份结果；第一版可先不做价格历史。 |
| P1 | 域名与 HTTPS | 部署完成后绑定 `caoxiaoysm.com`，验证中国和德国的 HTTPS 访问与登录回调。 |

当前使用邮箱魔法链接，不使用密码登录；Supabase 的“泄露密码保护”警告不会影响现有登录方式。未来若开放邮箱密码登录，应在 Auth 设置中启用该保护。

## 可以放到第二版

- 自动音频转写、关键帧 OCR、视频理解和批量 AI 结构化。
- 来源版与个人版的可视化差异比较、细粒度回滚和多人共同编辑。
- 自动超市搜索、价格抓取、库存、购物清单、周菜单和营养计算。
- 微信登录、小程序、多厨房调度和协作任务分配。

## 推荐发布顺序

1. 先完成 10 条真实内容和 RLS 自动化测试。
2. 在本地与手机浏览器跑完 P0 主流程。
3. 创建仅本人可访问的部署，配置 Supabase 正式回调地址。
4. 绑定 `caoxiaoysm.com`、开启 HTTPS，并分别从中国和德国网络验证。
5. 稳定使用一周后，再决定是否开放公开只读分享。
