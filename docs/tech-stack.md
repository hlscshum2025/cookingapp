# 技术与软件方案

## 推荐架构

先开发响应式 Web App / PWA。它可以直接通过链接和二维码打开，也能在手机上“添加到主屏幕”。等核心流程稳定后，再评估微信小程序；这样不会一开始维护两套界面。

| 层 | 推荐选择 | 原因 |
|---|---|---|
| 前端 | Next.js + TypeScript | 页面、接口和分享链接可以放在一个项目中 |
| UI | Tailwind CSS + 组件库 | 快速制作手机优先界面 |
| 数据库 | Supabase PostgreSQL | 适合结构化菜谱、关系查询和后续扩展 |
| 登录 | Supabase Auth | 个人编辑权限与公开只读访问分开 |
| 图片 | Supabase Storage | 不把图片塞入 GitHub |
| 部署 | Vercel | 适合 Next.js，自动生成 HTTPS 链接 |
| 二维码 | 前端二维码库 | 把公开 URL 直接转为二维码 |
| 本地开发 | VS Code、Git、Node.js | 编辑 Markdown、代码和版本管理 |
| API 调试 | Bruno 或 Postman（可选） | 调试导入与菜谱接口 |
| 设计 | Figma（可选） | 先做页面原型和手机布局 |

## AI 适合做什么

- 根据标题、简介、字幕草稿提取候选菜名、食材、厨具和步骤
- 生成分类标签候选
- 翻译中英德食材名称
- 提议德国常见替代品
- 把做菜日志整理成清晰的“下次改进”
- 检查重复食材和别名

AI 输出不能直接成为最终数据，尤其是用量、温度、过敏原、无麸质判断、营养和健康相关标签。界面应始终提供人工确认与编辑。

## 不需要额外购买的软件

第一版可使用免费或免费额度工具完成。真正可能产生费用的部分是：数据库/图片或部署流量超过免费额度、批量 AI API 调用，以及可选的自定义域名。

不建议为 197 个视频一开始就引入复杂的数据仓库、向量数据库、独立微服务或原生 App 开发环境。

## 密钥管理

创建本地 .env.local，只保存本机和部署平台环境变量。仓库中仅提交 .env.example，不得提交：

- Supabase service role key
- AI API key
- B 站 Cookie / SESSDATA
- 任何个人登录凭据

## 建议目录（开发阶段）

```text
app/                 页面和接口
components/          UI 组件
lib/                 数据库、导入、翻译等逻辑
supabase/migrations/ 数据库版本
data/seeds/          初始标签和公开词典
docs/                产品与技术文档
scripts/             收藏夹导入和数据清洗脚本
tests/               自动化测试
```
