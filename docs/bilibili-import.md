## 导入范围

只导入必要的公开视频元数据：BV 号 / AV 号、视频 URL、标题、UP 主名称与 ID、封面 URL、简介、发布时间、收藏夹 ID、导入时间和视频可用状态。

不下载或重新分发视频文件，不绕过付费、登录或访问限制。

## 推荐的三段式流程

### 1. 获取清单

优先调用 B 站页面正常使用的公开接口或由用户登录状态下导出。若接口需要 Cookie，只允许用户在自己的电脑本地运行脚本；Cookie 不上传、不提交 GitHub。

### 2. 提取候选菜谱

按可靠性从高到低使用：

1. 视频简介/置顶文字中的明确配方
2. 用户提供或合法可获取的字幕
3. 标题和简介推断的候选标签
4. 人工观看后补充

AI 不能从一个模糊标题臆造精确克数、温度或时间。缺失信息应显示“待补充”。

### 3. 人工校对入库

每条视频进入处理队列：未处理、AI 已提取待校对、已校对、已转成菜谱、跳过（不是菜谱/重复/失效）。

## 本地导出文件

如果自动导入受限，可由浏览器或本地脚本生成 bilibili-favorites.json。最小格式：

```json
[
  {
    "bvid": "BVxxxxxxxxxx",
    "url": "https://www.bilibili.com/video/BVxxxxxxxxxx",
    "title": "视频标题",
    "uploader": "UP主",
    "cover_url": "https://...",
    "description": "简介"
  }
]
```

导出文件若包含私人收藏信息，默认不公开提交；仓库只放脱敏样例。正式数据进入 Supabase。

## 导入验收

- 实际条数与收藏夹页面一致，BV 号去重，分页无遗漏
- 失败和失效视频单独列出
- 重复运行不会重复建菜谱
- 中断后可以从上次进度继续
- 保留原始元数据用于追溯
