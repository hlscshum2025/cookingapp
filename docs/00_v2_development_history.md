# 00｜CookingApp V2 历史工作流程与研发经验

更新日期：2026-08-31
用途：记录 V2 从立项到当前阶段的实际研发顺序、方案变化、验证结果和可复用经验。V1 经验继续保存在 [`00_v1_technical_experience.md`](./00_v1_technical_experience.md)；未来计划以 [`01_product_roadmap.md`](./01_product_roadmap.md) 为准，当前工作以 [`02_v2_workboard.md`](./02_v2_workboard.md) 为准。

## 1. V2 的工作闭环

```text
真实使用反馈 / 新设想
  → 99 记录问题、环境与影响
  → 01 决定版本、优先级、延期或放弃
  → 02 写当前任务、前置条件和完成定义
  → 先改 DEV 数据库并验证 RLS
  → 编码、构建、自动测试
  → 同步 PROD migration
  → GitHub main
  → Sites 发布
  → 桌面 / 手机 / 双账号实机验收
  → 回写 99、02 与发布记录
```

不能把“代码已写”“migration 已执行”“网站已发布”“用户已验收”混成同一种完成状态。

## 2. 2026-08-11｜V2 从账号、安全和真实录入问题开始

- 登录与注册拆分，确认邮件重发、密码恢复和邮箱密码登录分别处理；
- Turnstile 加入登录/注册防滥用边界，密钥只通过运行环境读取；
- 建立 `user_roles`，角色不放在用户可修改的 metadata 或 profile 字段中；
- 收紧跨用户关系的 RLS，避免只改 `recipe_id` 就关联或读取其他人的记录；
- 导入 JSON 从“直接制造菜谱”改为“只建立来源待办”，正式菜谱必须经过手工核验与保存；
- 手动录入增加多种真实中餐单位、来源证据、草稿保护、播放器和返回路径；
- 手机底栏按真实使用频率重排，并把低频入口放入“更多”。

经验：先解决身份、所有权和数据语义，再做更多自动化。错误的数据状态比少一个自动导入按钮更难修复。

## 3. 2026-08-12～13｜公开菜谱、采购与本地化边界

- 私人菜谱不再直接切成公开；改为用户提交安全快照、管理员审核、独立公开表；
- 成品图片、公开点赞、采购车和线上冰箱逐步进入 V2；
- 简体与繁体不采用“一键字符转换覆盖全部内容”的方案；
- 语言结构确定为 `zh-CN`、`zh-TW`、`en`、`de`，界面词条、厨房地区词汇和用户原文分层；
- 用户录入的菜名、步骤和日志永远保留原文，切换语言只改变界面与 canonical 词条显示。

经验：公开数据要用白名单快照；语言切换要区分 UI、地区词汇和用户内容。

## 4. 2026-08-14～18｜多来源导入与图像研究路线

- 建立统一来源适配层，B站、下厨房、小红书和普通网页共享来源待办结构；
- 下厨房通过公开 MIP 页面读取标题、作者、用料和步骤，失败时保留原链接；
- 小红书服务器自动抓取被放弃，改为用户在浏览器完成人工验证后运行页面提取器，再带回 CookingApp JSON；
- 自动视觉导入拆分为图像预处理 → OCR → 版面解析 → 词典映射 → 人工确认；
- 小票 OCR、CORD、PaddleOCR 和手机本地 OCR 适配器进入研究路线；
- ASR、YOLO 和多模态证据融合明确放到 V4，不阻塞 V2。

经验：受登录、验证码和跨域限制的平台，不能把“打开原页面”误写成“已经接通自动导入”。能力提示必须说明自动、半自动、手工和开发中的真实边界。

## 5. 2026-08-15｜第一轮 V2 正式发布

- DEV / PROD 数据库结构对齐，数据库差异记录清空；
- GitHub main 与 Sites 源码统一；
- 发布门禁中发现的源码断言仍指向重构前组件和旧文案；
- 将断言改到真实承载功能的组件，并恢复全部自动测试；
- Sites Version 14 发布，自定义域名继续指向正式站。

经验：源码断言测试检查的是“关键实现与安全提示还在不在”，不是让用户手工点击。重构组件后必须同步测试目标，不能因为功能仍可用就删除发布门禁。

## 6. 2026-08-22｜导入中心、反馈闭环与语言骨架

- 两个 Supabase 项目恢复为健康运行状态；
- 导入中心改为先选 B站、小红书、下厨房或“更多平台”，再展开对应操作区；
- 选中平台与操作区融合，其他平台降为次要，减少多个入口同时争夺注意力；
- 能力提示采用“符号 + 短文字”，明确内嵌视频、自动读取、页面提取、手工核验和 OCR 开发中；
- 操作说明、脚本与批量 JSON 流程改为按需展开；
- 所有登录用户都能提交平台建议；只有管理员能查看全体队列、分级和调整状态；
- 实时反馈存入 Supabase，确认后的产品决策再摘要到 `99`，不让网页直接改公开 GitHub 文档；
- 加入四语言界面骨架和 `profiles.locale` 偏好；桌面右上角可切换，手机在设置和“更多”账号卡片中查看账号信息；
- 更新源码断言并恢复 40/40 自动测试。
- 将语言切换和“设置”统一收进所有页面共用的右上角账号菜单，移除左侧“设置”和独立 Supabase 状态胶囊；头像以绿色填充表示云端已实际连通，未连通时保持白色并显示 1 条状态角标；设置页“环境配置”也仅在连接有效时变为绿色。
- 导入平台选项卡与内容区改为同一个圆角外壳：统一左右边界、阴影和底部圆角，选中标签跨过内部水平分隔线自然连接内容；窄屏使用单行横向滑动标签，避免两行标签无法与内容面板对应。
- 总览“线上冰箱”升级为“我的粮仓”，分为线上冰箱与线上储物柜并分别新增食材；库存卡片加大，红色 × 先进入可撤销删除队列，二次确认后批量删除。设置页将备份与恢复折叠进账号权限卡；导入平台默认全部收起，同一平台按钮负责展开/收回。
- 导入平台收起态再次优化：四张选项卡在外框内部等高居中、四边留白，不再与外边框接轨；手机端改成两列网格并收起能力小标签，导入表单和文件框限制在视口内；长外语文案允许安全换行，减少德语等语言造成的撑宽错位。

经验：在线用户反馈属于业务数据，GitHub 的 `99` 属于研发治理记录，两者不能共用一个可被前端直接修改的存储入口。

## 7. 2026-08-25｜下厨房真实样本修复与视觉任务前移

- 用户截图确认下厨房 `107345578` 只出现 5 个步骤、0 条食材；页面本身并未删除用料，移动页仍提供 Recipe JSON-LD，MIP 页面也仍有 8 条 `ing-name / ing-amount`；
- 解析器增加三层保护：优先读取移动页 JSON-LD、失败回退 MIP、再直接读取用料结构化行；同时支持 `500g鸡翅` / `2勺酱油` 这种无空格写法和字符串编号步骤；
- 使用真实抓取页面离线验证得到 8 条食材、5 个步骤，并新增两个 `107345578` 结构回归测试；2026-08-25 生产构建与 50/50 自动测试通过，最终仍由用户在本地界面点击“识别并读取”验收；
- 德国邮箱验证已由用户确认通过，可靠性表关闭该问题；其他技术债增加“为什么做、用户要做什么、是否当前阻塞”的通俗解释；
- 为成本核算和线上冰箱，德国小票 OCR、小红书截图 OCR、YOLO / YOLO-World 食材识别和实例分割进入 V2 当前主线；
- 现有四语言切换骨架继续保留，但全站翻译、地区词汇审校、邮件/错误文案和四语言布局矩阵移到 V3；
- 词典扩充排在导入与识别之后，顺序变为：导入修复 → OCR/视觉识别 → 词典扩充；
- 本批只更新代码和 GitHub，不创建 Sites 新版本，不修改 PROD。

经验：第三方页面解析不能只依赖一个标题正则或一个页面版本；真实来源应有结构化数据、HTML 行和替代页面三层降级。超市视觉识别也不是“装一个 YOLO 就完成”，袋装果蔬必须用透明袋、反光、遮挡和真实手机环境单独验证，并把视觉、OCR、条码、重量都当成可冲突的候选证据。

## 10. 当前仍需注意

- 免费 Supabase 项目在约 7 天低活动后仍可能自动暂停；正式站的真实数据库请求通常足以保持 PROD 活跃，DEV 需要按研发节奏恢复；
- 四语言目前只是保留的 UI 骨架；完整语言系统已移到 V3，不再阻塞 V2；
- 官方平台标识只用于来源识别，不能暗示 CookingApp 与平台存在官方合作；
- 小红书仍是“分享识别 + 原站查看 + 页面提取器 + 人工核验”，不是无条件服务器直连；
- 任何 OCR、ASR 或自动结构化候选在人工确认前不能静默改写菜谱、库存或成本；
- 词典分类与用户词汇提案已进入 V2 计划，但尚未实施数据库和审核界面。
