# 02｜CookingApp V2 当前工作任务表

更新日期：2026-08-14  
当前阶段：V1 已结项，V2 正在开发。  
原则：这里只记录 V2 的实际工作、状态变化和验收结果；长期设想统一进入 [`01_product_roadmap.md`](./01_product_roadmap.md)。

## 1. 状态口径

一项功能必须依次区分：

```text
待设计 → 开发中 → 已合入 main → 已迁移 → 已部署 → 已实机验收
```

不能因为“代码写完”就直接标记完成。涉及数据库的功能必须单独确认 migration；涉及账号和公开数据的功能必须用至少两个账号验收。

### V2-P1｜繁体中文与台湾地区词汇

目标不是安装一个自动简繁转换插件，而是同时解决字符、界面文案和地区叫法。

| ID | 任务 | 当前状态 | 完成定义 |
|---|---|---|---|
| V2-I18N-01 | 建立 i18n 基础层 | 待设计 | UI 文案从组件中抽离；至少支持 `zh-CN`、`zh-TW`；缺失词条有明确 fallback。 |
| V2-I18N-02 | 账号语言偏好 | 待开发 | 设置页可选择语言，写入现有 `profiles.locale`；未登录时使用浏览器语言并允许手动切换。 |
| V2-I18N-03 | 台湾界面语言包 | 待开发 | 导航、按钮、状态、验证、错误、空状态和邮件相关提示均有人审校，不只做字形转换。 |
| V2-I18N-04 | 台湾厨房词汇层 | 待开发 | canonical 条目保持稳定；按 locale 展示“马铃薯/馬鈴薯、菜花/花椰菜”等地区名称与别名。 |
| V2-I18N-05 | 用户内容保护 | 待开发 | 用户录入的菜名、步骤和日志保留原文；切换界面语言不会永久改写数据。 |
| V2-I18N-06 | 搜索与导入兼容 | 待开发 | 简体、繁体和地区别名能命中同一 canonical 食材；导入原文仍可追溯。 |
| V2-I18N-07 | 双地区验收 | 待测试 | 用简中与繁中各跑登录、导入、编辑、筛选、采购和公开菜谱主流程；无截断或混合语言。 |

建议数据边界：

```text
UI message catalog
  └─ zh-CN / zh-TW

Kitchen term
  ├─ canonical_id
  ├─ locale
  ├─ display_name
  ├─ aliases[]
  ├─ source
  └─ verification_status
```

纯字符转换可以作为录入辅助或缺失词条 fallback，但不能成为数据库主词条，也不能自动覆盖用户原文。

## 4. 当前执行顺序

1. 对当前 `main` 做 build / test 回归，先解决任何源码断言或类型错误。
2. 重新发布 Sites，桌面和手机验收采购勾选、线上冰箱、下厨房 MIP、小红书网页提取器。
3. 用至少两个账号确认 pantry RLS、公开审核和公开点赞不会跨用户。
4. 完成多来源真实样本：B 站、下厨房、小红书、通用文本各至少一条。
5. 建立 `zh-CN` / `zh-TW` i18n 骨架和台湾厨房词汇最小集。
6. 再进入采购合并、成本结构、SMTP、监控和架构拆分。
