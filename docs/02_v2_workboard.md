## 1. 状态口径

一项功能必须依次区分：

```text
待设计 → 开发中 → 已合入 main → 已迁移 → 已部署 → 已实机验收
```

不能因为“代码写完”就直接标记完成。涉及数据库的功能必须单独确认 migration；涉及账号和公开数据的功能必须用至少两个账号验收。

延迟结论：旧代码确实存在强制整页刷新，不是 Supabase 必须这样做。保存到后台产生网络延迟是正常的，但大型应用通常采用“本地/缓存先更新 + 后台写入 + 局部失效/实时推送”，不会每改一条数据就重载整套 GUI。本批次先移除明确的整页刷新；多账号协作时再根据规模选择 Supabase Broadcast / Realtime，而不是为单人编辑一直保持全表订阅。

批量处理结论：现在不必为了“将来可能很多”先一次性录完全部菜谱。先完成小红书截图、小票和食材识别，再实现 `V2-BATCH-01`。届时可连续处理多份本机草稿，最后一键上传；正式数据仍以 Supabase 为准。当前词典是“代码内置基础词典 + Supabase 个人补充”的混合结构，纯文字不会成为主要空间压力；真正占空间的是原图、视频、训练集和模型权重。

### V2-P1｜小票 OCR、采购入库与食材视觉识别（当前主线）

目标：先完成“德国超市小票 → 可审核采购数据 → 成本/线上冰箱”，再完成“小红书截图 → 菜谱候选”和“冰箱/台面照片 → 食材候选”。V2 不要求从零训练大模型，但必须跑真实 baseline、保存错误样本并完成用户确认闭环。

术语：OCR = Optical Character Recognition（光学字符识别）。默认流水线是 **图像预处理 → OCR → 版面/行解析 → 商品归一化 → 人工确认 → 写入采购/库存**，不是先 OCR 再靠 OCR 做图像预处理。

|---|---|---|---|

| [Ultralytics YOLO](https://github.com/ultralytics/ultralytics) | 快速跑检测、分割、分类和导出 baseline | 通用权重不能覆盖所有德国商品、袋装散装果蔬；正式商业使用前需确认 AGPL / Enterprise 许可。 |
| [YOLO-World](https://github.com/AILab-CVC/YOLO-World) | 用文字提示快速试未知类别和开放词汇检测 | 零样本结果不等于稳定库存识别；GPL-v3 / 商业许可需单独审查。 |
| [Segment Anything](https://github.com/facebookresearch/segment-anything) | 从框/点生成实例 mask，辅助标注和分割 | SAM 只负责“分出物体”，本身不保证知道这是苹果还是番茄。 |
| [Grocery Store Dataset](https://github.com/marcusklasson/GroceryStoreDataset) | 5125 张自然商店图、81 个细类 / 42 个粗类，适合分类迁移学习 | 不覆盖 CookingApp 的家庭冰箱、透明袋反光和德国本地全部品类。 |
| [RPC](https://github.com/RPC-Dataset/RPC-Dataset.github.io) / [Unitail](https://arxiv.org/abs/2204.00298) | 商品结账、货架检测、包装文字和商品匹配 benchmark | 更偏包装商品/零售场景，不能替代散装果蔬与自有真实测试集。 |

超市称重识别通常不是单一算法，而是固定相机/托盘、受控距离、商品图像、重量、PLU/条码、包装 OCR 和多帧结果的组合。透明袋会带来反光、折射、遮挡和实例粘连；CookingApp 首版应先做到“快速给出可编辑候选”，不把超市封闭环境下的准确率直接当成手机冰箱场景准确率。

#### CORD 的 V2 使用方法

1. 官方项目：`clovaai/cord`，优先使用 CORD v2；许可证为 CC BY 4.0。
2. CORD 是**收据后 OCR 解析学习数据**，主要为印度尼西亚收据，不直接等价于德国超市小票。
3. 下载后先读懂一条样本：原图 → `valid_line`/box/text → `gt_parse` 结构化标签；不要第一天就训练网络。
4. 用 CORD 的 train/dev/test 原划分做 baseline，记录 OCR 字符错误、行分组错误和字段解析错误。
5. **不需要把 CORD 1000 张全部重新人工核验。** 数据集已有标注；学习阶段抽查约 20–50 张确认自己理解标签即可。若以后建立自己的德国小票数据集，则模型预标注后仍要人工复核 ground truth。
6. CORD 只用于算法学习/benchmark；CookingApp 真正上线前，应另外收集不同德国超市、不同光线/折痕/角度的小票作为独立测试集。

推荐代码边界（真正开始写 Python 时再创建）：

```text
services/
  vision/
    pyproject.toml          # 或 requirements.txt
    receipt_ocr/
      __init__.py
      preprocess.py         # OpenCV
      ocr.py                # PaddleOCR Adapter
      parser.py             # 商品行/数量/价格解析
      schema.py             # ReceiptOcrDraft
      main.py               # 本地 CLI / 服务入口，可自行命名
    tests/
```

`main.py` 不是 Python 项目的强制文件。当前 CookingApp 是 Next.js/TypeScript 项目，所以仓库根目录没有 `main.py` 完全正常。
