# 99｜CookingApp 问题反馈与调整记录

更新日期：2026-08-22
用途：保留每条真实反馈从发现、复现、分级、调整到验证的完整链路。功能计划写入 `01`，当前实施写入 `02`，发布结果写入 CHANGELOG。

## 1. 记录规则

每条反馈使用稳定编号 `FB-YYYYMMDD-NN`，不因修复或版本结束删除。

必填信息：

- 发现日期、反馈人和使用环境；
- 入口、操作步骤、期望结果、实际结果；
- 严重级别与影响范围；
- 原因；
- 调整方案、相关提交/migration/部署；
- 验证账号、设备、环境和结果；
- 若不处理，记录延期、替代或放弃原因。

### 严重级别

| 级别 | 定义 | 处理要求 |
|---|---|---|
| P0 | 数据丢失、越权、安全泄露或核心流程完全阻塞 | 停止发布，优先修复并增加回归测试。 |
| P1 | 主流程明显受损但存在可靠绕行 | 进入当前版本工作表，发布前处理或明确延期。 |
| P2 | 易用性、文案、布局或低频功能问题 | 排期处理，不阻塞紧急修复。 |
| P3 | 建议、偏好或实验性想法 | 先进入路线图候选池。 |

## 3. 已记录反馈

### FB-20260811-01｜“首次设置”让用户误以为是注册

- 状态：已验证
- 级别：P1
- 实际结果：首次设置/找回密码排在注册前，注册入口不够明显。
- 原因：把注册初始化与密码恢复复用为同一心智模型。
- 调整：彻底删除“首次设置”；注册改为醒目整行按钮；确认邮件重发和忘记密码分离。
- 验证：登录、注册、重发确认邮件和找回密码入口分别可用。

### FB-20260811-02｜注册确认邮件与密码找回混用

- 状态：已验证
- 级别：P1
- 实际结果：未收到注册邮件时请求进入 `/recover`，无法正确补发确认邮件。
- 原因：两个 Supabase Auth 接口和页面入口复用错误。
- 调整：新增独立“注册后没收到确认邮件？”流程并接入 Turnstile。
- 后续：德国邮箱未达仍作为 V2 跨地区投递问题跟踪。

### FB-20260811-03｜JSON 导入用途和操作方法不清楚

- 状态：已验证
- 级别：P2
- 实际结果：用户不知道 F12 中复制什么、如何保存 JSON、导入后会发生什么。
- 调整：加入五步说明；明确 JSON 只建立来源待办，不会自动生成完整菜谱。

### FB-20260811-04｜食材单位只有克不符合真实中式菜谱

- 状态：已验证
- 级别：P1
- 实际结果：葱姜蒜、调味料、柠檬等无法用片、段、圈、勺、个或比例表达。
- 调整：取消默认 `g`，加入多单位建议并允许自由输入；保留原始用量文字。
- 后续：成本模块不得强制把所有单位换算为克。

### FB-20260811-05｜手动录入离开页面后容易丢失

- 状态：已验证
- 级别：P1
- 调整：按账号和来源隔离浏览器草稿；云端正式保存成功后才清理。

### FB-20260811-06｜B站小播放器难以控制且误跳原站

- 状态：已验证
- 级别：P1
- 实际结果：暂停、音量和尺寸不便；点击播放器其他区域可能跳转 B 站。
- 调整：增加显式“打开原视频”、标准/放大切换，关闭自动播放与弹幕参数，悬浮播放器避开手机底栏。

### FB-20260811-07｜二级页面缺少统一返回上一层

- 状态：已验证
- 级别：P2
- 调整：建立复用 `SubpageBack`，加入详情、新建、编辑、厨房模式等二级页面，并统一页面内位置。

### FB-20260811-08｜标签总览与菜谱查找脱节

- 状态：已验证
- 级别：P1
- 调整：升级为食材、UP主、内容标签和状态组合筛选中心；食材和UP主从领域字段自动参与，不重复塞进 tags。

### FB-20260812-01｜JSON 导入制造大量空菜谱

- 状态：已验证
- 级别：P0
- 原因：导入层把“收藏来源”错误等同于“正式菜谱”。
- 调整：JSON 只写 `source_videos`；手工保存菜谱后才完成来源待办；支持删除不需要的来源。
- 验证：来源待办、保存、完成和菜谱库状态不再互相污染。

### FB-20260812-02｜公开菜谱不能直接暴露私人原稿

- 状态：已验证
- 级别：P0
- 原因：直接切换 visibility 无法保证字段白名单和修改复审。
- 调整：使用私人申请、管理员审核和独立公开快照；私人日志与导入证据不进入公开表。

### FB-20260812-03｜本地开发被 Cloudflare runtime 阻塞

- 状态：已验证
- 级别：P1
- 调整：本地 Vite 与 Cloudflare plugin 解耦；增加平台中立 runtime config API；localhost 不启用 Turnstile。

### FB-20260812-04｜采购车出现在登录页

- 状态：已修复
- 级别：P2
- 调整：未登录页面不挂载业务采购车，手机位置避开底部导航。

### FB-20260813-01｜繁中不能只做自动字符转换

- 状态：已排期至 V2
- 级别：P1
- 反馈：台湾用户不仅使用繁体字，还存在不同地区词汇；自动转换插件不能解决语义差异。
- 调整方案：建立 `zh-CN` / `zh-TW` UI 语言包、台湾厨房词汇层和 locale 搜索别名；保留用户原始菜谱内容，不自动覆盖。
- 关联：`02` 中 V2-I18N-01～07。

### FB-20260813-02｜组件重构后 3 条源码断言测试失效

- 状态：已修复并验证
- 级别：P0（发布门禁）
- 环境：GitHub `main` 本地构建与测试
- 实际结果：生产构建成功；27 项测试中 24 项通过、3 项失败。
- 原因：导入页重构成薄页面后，测试仍只读取 `app/imports/page.tsx`，没有读取实际承载文案和播放器的 `components/ImportWorkspace.tsx`；设置页测试仍断言旧文案“已读取 Supabase 配置”，源码已改为“已连接 Supabase”。
- 调整：把断言指向真实组件并同步当前文案；本轮导入中心和多语言重构后再次更新断言，保留对未登录提示、B站播放器、平台入口、手工录入、账号设置和反馈 RLS 的覆盖。
- 验证：2026-08-22 生产构建成功，40/40 自动测试通过。
- 影响判断：这是研发自动测试，不要求用户手工操作；用户只需在发布后按正常流程体验导入中心。
- 关联：`02` 中 V2-P0-06。

### FB-20260822-01｜导入中心多个入口和长说明同时出现，界面混乱

- 状态：已修复，待部署实机验证
- 级别：P1
- 实际结果：链接入口、平台说明、待办、JSON 和自动导入占位同时争夺注意力，用户难以判断先点哪里。
- 调整：上方只保留 B站、小红书、下厨房和“更多平台”；点击后只展开一个平台工作区，选中图标放大并与下方区域融合，其他图标降为次要；脚本、代码和流程说明改为按需展开。
- 能力提示：使用“符号 + 短文字”，明确视频、自动读取、页面提取、手工核验和 OCR 开发中，不只用颜色表示状态。
- 验证：构建与源码回归通过；仍需桌面和手机各完成一次真实来源导入。

### FB-20260822-02｜手机端不容易看到账号信息和语言设置

- 状态：已修复，待部署实机验证
- 级别：P1
- 实际结果：手机底栏没有账号入口，设置页也没有语言切换。
- 调整：手机“更多”增加当前账号卡片和设置入口；设置页增加语言选择；桌面右上角增加紧凑语言选择。
- 数据：界面偏好写入 `profiles.locale`，同时保留本机 fallback；支持 `zh-CN`、`zh-TW`、`en`、`de`。
- 约束：当前只完成导航、状态和主要页面骨架，用户菜名、步骤和日志保留原文。

### FB-20260822-03｜需要从导入中心提交后续平台建议

- 状态：已开发，数据库 migration 待最终同步核验
- 级别：P1
- 调整：所有登录用户都可以从“更多平台”提交平台名称、需求说明和可选示例链接；用户只能读取自己的反馈。
- 管理边界：管理员设置区可查看全体反馈、分级并调整状态；普通用户不能进入全体审核队列。
- 存储：实时提交保存在 Supabase `feedback_submissions`；GitHub `99` 只保存确认后的研发问题、调整结论与验证，不作为网页直接写入的数据库。

## 5. 从反馈回到研发的闭环

```text
真实使用反馈（99）
  → 分级与复现
  → 路线图决策（01）
  → 当前版本任务与完成定义（02）
  → 开发 / migration / 测试 / 部署
  → 实机验证并回写（99）
  → 发布日志（CHANGELOG）
  → 版本结项经验（00 类复盘）
```

在线反馈与本文件的边界：

```text
网页提交 → Supabase feedback_submissions（私有业务记录）
  → 管理员分级 / 排期 / 关闭
  → 确认会影响产品的事项摘要到 99
  → 01 / 02 / migration / 开发 / 验证
```
