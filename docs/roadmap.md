- [x] 确认 GitHub + Supabase 的数据分层

- [ ] 首页与筛选、菜谱详情、菜谱编辑、做菜日志

**完成标志：** 无需写代码也能通过原型走通主要流程。

## 阶段 2：MVP 开发

- [ ] 初始化 Next.js / TypeScript
- [ ] 建立 Supabase 项目与 migration
- [ ] 登录和权限
- [ ] 菜谱、版本、食材、厨具、步骤 CRUD

**完成标志：** 可以在手机上管理全部菜谱，公开链接不会泄露私人日志。

## 阶段 3：批量整理 197 个视频

建议分批处理，每批 20–30 条：

1. 清理重复、失效和非菜谱视频
2. AI 生成候选信息
3. 人工校对食材、用量、步骤和标签
4. 添加自己的成功版本和心得
5. 统一中英德食材名及德国替代品

不要等待 197 条全部整理完才上线；先让 10 条、30 条、100 条各自形成可用版本。

## 阶段 4：增强功能

- [ ] 库存与购物清单、周菜单
- [ ] 营养估算与来源标注
- [ ] 个人饮食目标规则和智能推荐
- [ ] 数据导入导出
- [ ] 决定是否开发微信小程序

## 决策原则

- 个人修改记录比“完整搬运视频”优先
- 可追溯和可编辑比全自动优先
- 健康相关内容必须标记来源和人工确认状态
- 首版先用响应式 Web/PWA 获得链接与二维码
- 数据必须可以导出，避免平台锁定
